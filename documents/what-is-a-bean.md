# 図鑑に載せるものを決める仕組み

図鑑に並べたいのは「いま買える焙煎豆」だけ。ところが店のECには、器具・グッズ・
講座・カプセル・絵画まで同じ棚に並んでいる。どれを載せるかを決めるのがこの仕組み。

## これまでの形と、その限界

商品名の綴りだけを見て、豆でないものを正規表現で落としていた。しかもその一覧を
表示側（`frontend/components/lib/isCoffee.js`）と生成側
（`scripts/build_frontend_data.py`）に**手で二重に**書いていた。

この形は収束しない。

- 店は世界中にあるので、語の一覧が全部の言語をおおうことは無い。英語と日本語だけで
  書かれていた時期には、台湾の店の `濾杯`（ドリッパー）や `膠囊`（カプセル）が
  そのまま豆として並んでいた
- 語を広げると、こんどは**本物の豆を巻き添えにする**。実際に落ちたもの:
  `Mwendi Wega`（ケニアの水洗工場。Wega はマシン名でもある）、
  `キッサブレンド`（キッ**サブレ**ンド）、`Coffee & Tea`（tea を含む）、
  `Filters`（紙）と `Filter`（フィルター用の焙煎＝豆）
- 消えたことは画面を見ても分からない。図鑑から静かに減るだけ

根っこの問題は、**巡回が持っていた証拠を捨てていた**こと。店は
`product_type` や `tags` に「これは何か」を書いてくれているのに、それを一度使って
捨て、表示側で商品名から当て直していた。

## いまの形

判断を3段にして、確かなものから順に見る。

```
1. FORM        形が豆でないもの        店が何と言おうと載せない
2. 店の申告     product_type / tags    ここで通せば、名前は見ない
3. GUESS       名前からの当て推量      店が何も言っていないときだけ
```

### 1. FORM ── 形が豆でないもの

カプセル・ドリップバッグ・生豆・缶・ギフト箱・定期便・器具・講座。
中身がコーヒーであっても、**焙煎豆の袋ではない**もの。

店が「Coffee」と言っていても載せない。店にとってカプセルもギフト箱もコーヒーだが、
図鑑が並べたいのはそれではないため。

### 2. 店の申告 ── `bean.kind`

巡回が `product_type` と `tags` を読んで、`"c"`（コーヒーだと書いてある）を
豆に付けて運ぶ（`src/crawler.py` の `shop_says`）。

店の申告は商品名の綴りより確かで、**言語にも左右されない**（中国語の店でも
`product_type` は英語のことが多い）。

ただし非対称である。

- 「**コーヒーでない**」の証明には**強い**。`Espresso Machine`、`Arts & Entertainment`、
  タグ `Classes` は、それだけで確定する（巡回がその場で落とす）
- 「**これは豆だ**」の証明には**弱い**。`Coffee` にはカプセルもギフト箱も粉も入る

だから `kind === "c"` は「無条件で載せる」ではなく、「**名前から当てるのをやめてよい**」
の合図として使う。FORM は素通しにしない。

### 3. GUESS ── 名前からの当て推量

店が何も書いていない商品にだけ使う。固有名詞の一覧や、菓子・機種名など。
当たり外れがあるので、ここで本物の豆を落とす事故が起きていた。
店が豆だと言っているものは、もうこの巻き添えに遭わない。

## 漏れの見つけ方

一覧は完全にならない。だから「探す道具」を用意して、定期的に回す。

| 道具 | 何を見るか |
|---|---|
| `scripts/price_outliers.mjs` | 100gあたりの値段の両端。マシンは¥40万、決済ページは¥1 になるので端に固まる |
| `scripts/audit_product_types.py` | 店が実際に使っている `product_type` の集計。想像で線を引かないため |
| `scripts/check_products.py` | 名前では分からない商品を、店の商品ページで確かめる |

後ろ2つは runner で走らせる（`.github/workflows/probe-roasters.yml`）。
開発環境からは外に出られないため。

**値段は「探す道具」であって「落とす基準」ではない。** 香港には ¥170/100g の
本物の豆があり、オークションロットには $3,600/100g の本物がある。線を引くと
どちらかを殺す。

## 壊れていないことの確かめ方

| テスト | 見るもの |
|---|---|
| `tests/test_is_coffee.mjs` | 落とすべき名前・残すべき名前・店の申告つきの3つ |
| `tests/test_looks_like_coffee.py` | 巡回側の分類の読み方。分類名は実在のものだけ |
| `tests/test_origin.py` | 産地の読み取りと「不明」の扱い |

いずれも点検（`.github/workflows/checks.yml`）で毎回走る。

**規則を足すときは、まずテストの「豆」の側を見ること。** 広すぎる語を足して
本物の豆を消しても、画面を見て気づくことはできない。
