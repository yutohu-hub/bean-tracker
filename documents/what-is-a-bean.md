# 図鑑に載せるものを決める仕組み

図鑑に並べたいのは「いま買える焙煎豆」だけ。ところが店のECには、器具・グッズ・
講座・カプセル・絵画まで同じ棚に並んでいる。どれを載せるかを決めるのがこの仕組み。

## これまでの形と、その限界

商品名の綴りだけを見て、豆でないものを正規表現で落としていた。しかもその一覧を
表示側（`frontend/components/lib/isCoffee.js`）と生成側
（`scripts/build_frontend_data.py`）に**手で二重に**書いていた。

この形は収束しない。

- 店は世界中にあるので、語の一覧が全部の言語をおおうことは無い。英語と日本語だけで
  書かれていた時期には、台湾の店の `濾杯`（ドリッパー）や `膠囊`（カプセル）が
  そのまま豆として並んでいた
- 語を広げると、こんどは**本物の豆を巻き添えにする**。実際に落ちたもの:
  `Mwendi Wega`（ケニアの水洗工場。Wega はマシン名でもある）、
  `キッサブレンド`（キッ**サブレ**ンド）、`Coffee & Tea`（tea を含む）、
  `Filters`（紙）と `Filter`（フィルター用の焙煎＝豆）
- 消えたことは画面を見ても分からない。図鑑から静かに減るだけ

根っこの問題は、**巡回が持っていた証拠を捨てていた**こと。店は
`product_type` や `tags` に「これは何か」を書いてくれているのに、それを一度使って
捨て、表示側で商品名から当て直していた。

## いまの形

判断を4段にする。最初の1段だけが「足し算」で、残りは「引き算」。

```
0. 門（取り込み）  豆である証拠があるか   証拠が無ければ、そもそも取らない
1. FORM           形が豆でないもの       店が何と言おうと載せない
2. 店の申告        product_type / tags   ここで通せば、名前は見ない
3. GUESS          名前からの当て推量     店が何も言っていないときだけ
```

### 0. 門 ── 豆である証拠があるか（`has_bean_evidence`）

1〜3 はどれも「豆でないものの名前を数える」引き算で、上に書いたとおり
一覧が終わらない。**知らない言葉の雑貨は、いつまでも漏れる。**

そこで取り込みの入口に、逆向きの判断を1つ置いた。豆でないものの名前は数えず、
**豆である証拠があるものだけ取る**。証拠が無ければ、こちらがその言葉を
知らなくても落ちる。ノルウェー語の水筒が落ちるのは、産地も精製も品種も
内容量も書かれていないからで、「水筒」という語を知っているからではない。

数える証拠は、商品名とタグにあるものだけ。

| 証拠 | 例 |
|---|---|
| 内容量 | `Gichathaini, 250g` `Seasonal Blend [200g]` `IO-E-15 / 8.8oz` |
| 産地 | `Ethiopia Guji` `Yirgacheffe Kochere` `Hacienda La Esmeralda` |
| 精製 | `Washed` `Natural` `Anaerobic` |
| 品種 | `Geisha` `SL28` `Pink Bourbon` |
| 焙煎度 | `浅煎り` `Medium Roast` |
| 挽き方の欄 | `Grind: Whole bean / Filter / Espresso` |

これに加えて、**店が `product_type` にコーヒーと書いていれば通す**。
名前が屋号だけの銘柄（`Morning Sun` `Big Truck` `Hoop`）は証拠が立たないので、
これが無いと本物の豆が消える。

**挽き方の欄**は器具にもTシャツにも付かないので、豆の側にしか出ない。
`grinder` は `\bgrinds?\b` に当たらないため、グラインダーは通らない（確認済み）。

**オンスとポンド**も内容量として読む。米国の店は袋を `8.8oz` `12oz` `5lbs` と
書く。読まずにいたため Onyx Coffee Lab の商品が落ちていた。

#### 門だけでは、すでに入っているものは消えない

門は「これから取らない」を決めるだけで、**すでに図鑑にあるものには触らない**。
巡回で取らなくなった商品は、誰も下げなければ `available=1` のまま残り、
`derive_status` はいつまでも「いま買える」を返す。

そこで、**棚から消えた商品を在庫なしに倒す**処理を入れた
（`src/state.py` の `_mark_withdrawn`）。これが無いと門の効き目が出ない。
売り終わった豆が「いま買える」として並び続ける問題も、同じ原因だった。

倒す対象は「今回1件以上返してきた店」に限る。巡回は442店を13に割って
1時間ごとに回しているので、今回見ていない店まで倒すと、一巡するまで図鑑が
売り切れだらけになる。この条件だと、スライス外の店・取得に失敗した店・
0件しか返さなかった店が自動的に全部外れる。

### 0-2. 店が種類を1つも書かないとき

`product_type` を全商品で空にしている店がある（実測44軒中1軒、Tim Wendelboe）。
そこでは店の申告という証拠が最初から使えないので、門が不当に厳しくなる。
実際 `Kapsokisio`（ウガンダの実在の銘柄）が落ちていた。

  - 商品名は水洗工場の名だけ。産地の語も内容量も焙煎度も品種も無い
  - `options` は `Default Title` のみ。規格も無い
  - 残っていたのは出荷重量 `311g` だけ

そういう店に限って、**出荷重量が袋らしい範囲（150〜1500g）にあること**を
証拠に数える。出荷重量は本来あてにならない（86%の商品に値が入っている）が、
店の申告が最初から使えない店に限れば話が別になる。

この店のTシャツやギフトカードも通るようになるが、どれも名前で外せるので
後段に任せる。**豆を落とす方が取り返しがつかない。**

（説明文の証拠を数える案も試した。`Kapsokisio` は救えず、救える数も30件ほどで、
代わりに通る雑貨が増えるだけだったので採らなかった。）

#### 線引きをどう決めたか

想像で決めなかった。実データ約5000件に6つの案を当てて、
**それぞれが何を落とすか**を見てから選んだ（`scripts/audit_bean_markers.py`）。

数字だけでは足りない。最初の版は「4916件→3915件」という数字だけ見て良しとしかけたが、
落ちた1001件から20件を無作為に取り出して並べたところ、そこに `Kapsokisio` が
混ざっていた。**落ちる物の中身を見るまで、決めてはいけない。**

最初に置いた2つの証拠は、測ってみたら使い物にならなかった。

- **Shopify の重量欄**は 86〜92% の商品に値が入っていた。あれは出荷重量なので
  マグにもTシャツにも付く。これを数えると証拠のある商品が94%になり、何も分けられない
- **説明文から読んだ産地**も当てにならない。`CLEVER DRIPPER` が「台湾」で産地ありに
  なっていた。台湾製だからで、豆だからではない

厳しい案（証拠2つ以上）は、店が自分でコーヒーと書いている商品を739件落とし、
その中に `オニバスブレンド` `シティローストブレンド` `Seasonal Blend [200g]` が
混ざっていた。**落ちた豆は画面に出ないので、間違えても誰も気づけない。**
だから緩い側に寄せ、店の申告がある商品は1件も落とさない条件を選んだ（実測0件）。

#### 門は中身を見ない

門は証拠の有無だけを見る。だからコーヒーの言葉が別の意味でも使われている商品は
通ってしまう。

- `Acaia Pearl S` ── Acaia はブラジルの品種名であり、はかりの銘柄でもある
- `ONA Natural Staple T-Shirt` ── Natural は精製方法であり、ふつうの英単語でもある
- `Origin Series Poster | Rwanda` ── 産地の語はあるが、売っているのは紙

これらは**名前を知っていれば外せる**ので、これまでどおり 1〜3 が受け持つ。
門が担当するのは、名前を知りようがないものだけ。

ここを締め直したくなったときのために、`tests/test_bean_evidence.py` に
「わざと通している」ことを書き残してある。門を厳しくすれば上の3つは落とせるが、
**同じ厳しさで本物の豆も落ちる**。

### 1. FORM ── 形が豆でないもの

カプセル・ドリップバッグ・生豆・缶・ギフト箱・定期便・器具・講座。
中身がコーヒーであっても、**焙煎豆の袋ではない**もの。

店が「Coffee」と言っていても載せない。店にとってカプセルもギフト箱もコーヒーだが、
図鑑が並べたいのはそれではないため。

### 2. 店の申告 ── `bean.kind`

巡回が `product_type` と `tags` を読んで、`"c"`（コーヒーだと書いてある）を
豆に付けて運ぶ（`src/crawler.py` の `shop_says`）。

店の申告は商品名の綴りより確かで、**言語にも左右されない**（中国語の店でも
`product_type` は英語のことが多い）。

ただし非対称である。

- 「**コーヒーでない**」の証明には**強い**。`Espresso Machine`、`Arts & Entertainment`、
  タグ `Classes` は、それだけで確定する（巡回がその場で落とす）
- 「**これは豆だ**」の証明には**弱い**。`Coffee` にはカプセルもギフト箱も粉も入る

だから `kind === "c"` は「無条件で載せる」ではなく、「**名前から当てるのをやめてよい**」
の合図として使う。FORM は素通しにしない。

### 3. GUESS ── 名前からの当て推量

店が何も書いていない商品にだけ使う。固有名詞の一覧や、菓子・機種名など。
当たり外れがあるので、ここで本物の豆を落とす事故が起きていた。
店が豆だと言っているものは、もうこの巻き添えに遭わない。

## 情報シート（産地・精製・風味・内容量）

図鑑に出す豆の中身。**空欄は空欄のまま出す。** 想像で埋めない。

### 埋まらない理由は、たいてい「店が書いていない」

実測（21店・豆1192件、products.json の説明文を最後まで読んだ場合）:

| | 空欄 |
|---|---|
| 産地 | 26.5% |
| 精製 | 35.0% |
| 風味 | 69.1% |
| 内容量 | 0.7% |

説明文を1200字で切っていたのを6000字に広げても、増えたのは産地3件・精製10件
（1192件中1.1%）だった。**取り方の問題ではなく、書かれていない。**

商品ページのHTMLを読む案も試したが採らなかった。空欄は埋まるものの、
ヘッダー・フッター・「他のおすすめ」まで読むため、**別の豆の産地**が付く。
18件中3件が食い違い、ギフト定期便に産地が付いた。空欄より間違いの方が悪い。

### 風味は「どの道で取ったか」も持つ

風味は2通りの道で取っていて、質が違う。豆ごとに `note_src` で残す。

| 道 | 割合 | 中身 |
|---|---|---|
| `label` | 14.2% | `Tasting Notes:` などの見出しの直後。`Grape, Guava, Floral` のような列挙 |
| `guess` | 18.0% | 見出しが無く、風味語が2つ以上ある行。`A comforting and sweet coffee with…` のような地の文 |

見出しが1件も無い店が多い（Five Senses 70件中0件、Coffee Collective 56件中0件）。
そういう店では `guess` が全量を支えている。混ぜて1つの欄に入れると、あとから
選び分けられない。集計するときに「確かな方だけ使う」を選べるようにしてある。

見出しの言い回しは店ごとに違うので、見つけるたびに足している
（`Tasting Notes` `Flavor notes` `Tastes Like` `味わい` `テイスティングコメント`、
`【】（）[]` で囲うもの、`Our tasting notes :` のように前置きが付くもの）。

**アレルギー表示は風味として採らない。** 原材料の欄にはナッツ・アーモンド・大豆と
風味語が並ぶので、そのままだと拾ってしまう（実測でチャイの
`MAY CONTAIN PEANUT, ALMOND` を風味にしていた）。

## 漏れの見つけ方

一覧は完全にならない。だから「探す道具」を用意して、定期的に回す。

| 道具 | 何を見るか |
|---|---|
| `price_outliers.mjs` | 100gあたりの値段の両端。マシンは¥40万、決済ページは¥1 になるので端に固まる |
| `audit_product_types.py` | 店が実際に使っている `product_type` の集計。想像で線を引かないため |
| `check_products.py` | 名前では分からない商品を、店の商品ページで確かめる |
| `audit_bean_markers.py` | 門の線引きを実データで比べる。案ごとに「何を落とすか」を出す |
| `audit_sheet.py` | 情報シートの空欄が「店が書いていない」のか「取り方が悪い」のかを分ける |
| `audit_notes.py` | 風味の量と質。見出しありと当て推量を分けて数え、店ごとの偏りも出す |
| `audit_product_page.py` | 商品ページのHTMLを読むと空欄が埋まるか。増える数と**食い違う数**を並べる |
| `collect_instagram.py` | 店のページから Instagram のアカウント名を集める |
| `probe_roasters.py` / `diagnose_shop.py` | 候補の店の下見と、取れない店の原因調べ |

巡回のログには、門で落とした数を店ごとに出している。取れた数だけ見ていると
**落としすぎに気づけない**（落ちた物は画面に出ない）。1件も取れなかったのに
大量に見送った店は `⚠ 全部見送った店` として名前を挙げる。

道具は runner で走らせる（`.github/workflows/probe-roasters.yml` の `tool` で選ぶ）。
開発環境からは外に出られないため。

### 道具を作るときの決まり

**増えた数だけを出す道具は作らない。** 必ず「増えた数」と「壊した数」を並べる。
実測でこうなった例がある。

- 商品ページを丸ごと読むと、空欄は埋まるが**別の豆の産地**が付いた
  （ギフト定期便に「パプアニューギニア」）。増えた12件の裏で3件が化けていた
- 風味を当て推量で拾うと、**アレルギー表示**を風味にしていた
  （`MAY CONTAIN PEANUT, ALMOND`）

増えた数しか見ていなければ、どちらも「改善」に見える。

**値段は「探す道具」であって「落とす基準」ではない。** 香港には ¥170/100g の
本物の豆があり、オークションロットには $3,600/100g の本物がある。線を引くと
どちらかを殺す。

## 壊れていないことの確かめ方

| テスト | 見るもの |
|---|---|
| `tests/test_is_coffee.mjs` | 落とすべき名前・残すべき名前・店の申告つきの3つ |
| `tests/test_looks_like_coffee.py` | 巡回側の分類の読み方。分類名は実在のものだけ |
| `tests/test_origin.py` | 産地の読み取りと「不明」の扱い |
| `tests/test_bean_evidence.py` | 取り込みの門。**通すべき豆**と、わざと通しているもの |
| `tests/test_notes.py` | 風味の取り出し。実際の商品ページで見た壊れ方をそのまま並べてある |
| `tests/test_shopify_adapter.py` | 商品のほぼ全部を運ぶ経路を、ネット無しで通す。欄の抜けを拾う |

いずれも点検（`.github/workflows/checks.yml`）で毎回走る。

**規則を足すときは、まずテストの「豆」の側を見ること。** 広すぎる語を足して
本物の豆を消しても、画面を見て気づくことはできない。
